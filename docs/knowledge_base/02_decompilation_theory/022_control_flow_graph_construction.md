# Article 022: Control Flow Graph Construction and Basic Block Identification

## 1. Executive Summary & Specification
A Control Flow Graph (CFG) $G = (V, E)$ is a directed graph where vertices $V$ represent **Basic Blocks** (linear sequences of instructions with single entry and single exit) and directed edges $E$ represent possible transfers of control.

## 2. Basic Block Identification Algorithm
An instruction at offset $i$ is a **Leader** if:
1. $i = 0$ (the entry instruction of the method).
2. $i$ is the target of any conditional or unconditional jump (`goto`, `if*`, `tableswitch`, `lookupswitch`).
3. $i$ is the target of an exception handler (`handler_pc`).
4. $i$ immediately follows any jump, switch, return, or `athrow` instruction.

Each basic block spans from a leader up to (and including) the instruction immediately preceding the next leader or terminal jump.

## 3. Edge Categorization
- **Fallthrough Edge**: Natural sequential flow from block $B_i$ to $B_{i+1}$ (valid when $B_i$ does not end in unconditional jump/return).
- **Branch Edge (True/False)**: Generated by conditional jump opcodes (`ifeq`, `if_icmpeq`).
- **Switch Edges**: Multiple out-edges corresponding to case keys and the default target.
- **Exception Edges**: Implicit edges connecting any instruction inside a protected range $[start, end)$ to the corresponding `handler_pc`.

## 4. NanoDecompiler C++ Engine Integration
In `resources/engine_cpp/src/cfg.cpp`:
- `CFG::build()` scans bytecode leaders, segments blocks, and establishes bidirectional adjacency lists (`preds`, `succs`).
- Exception edges are segregated into protected regions to prevent cycle pollution in standard dominator algorithms.
