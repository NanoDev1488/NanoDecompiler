# HANDOFF_21: v1.5 - настоящий баг в собственной правке из HANDOFF_17
# (NameError, был скрыт защитным except)

Продолжение расследования `DeluxeMenuConstructor.loadMenu()`. При повторной
проверке через полный traceback (не через `str(DecompileAbort)`, а через
`traceback.print_exc()` на ОБЩЕМ `except Exception`) нашёл: диагностическая
правка из `HANDOFF_17_GOTO_INVESTIGATION_AND_V141.md` (пункт 2 -
"пересечение стека упирается в обработчик исключений") сама была БИТА:

```
NameError: name 'self' is not defined
  File "engine.py", line 667, in _ensure_depth
    if self.cfg.blocks[pc].handler_types:
```

`_ensure_depth` - вложенная ФУНКЦИЯ (closure) внутри
`decompile_method_body`, не метод класса - там нет `self`, есть локальная
переменная `cfg` (видно на строке прямо ВЫШЕ: `preds =
cfg.blocks[pc].preds` - без `self`). Написал `self.cfg` по инерции
(привычка из structure.py, где ЭТО ДЕЙСТВИТЕЛЬНО метод класса
`Structurer` с `self.cfg`).

## Почему не поймали раньше

`except Exception` (общий защитный пояс) корректно поймал `NameError` и
превратил его в `"внутренняя ошибка декомпилятора: NameError: ..."` -
метод безопасно падал в честный байткод-фоллбэк, как и было задумано для
ЛЮБОЙ непредвиденной ошибки. Никакого испорченного вывода не было - просто
вместо ЗАДУМАННОГО понятного сообщения ("пересечение стека упирается в
обработчик исключений") пользователь/следующая сессия видели бы куда менее
информативное "внутренняя ошибка: NameError" (если бы вообще заглянули -
метод и так безопасно фоллбэчился, разница чисто в тексте объяснения).
Заметил только когда специально прогнал `traceback.print_exc()` через
временный debug-хук по этому конкретному методу.

## Фикс

Одна строка: `self.cfg.blocks[pc].handler_types` -> `cfg.blocks[pc]
.handler_types` (убрать `self.`).

## Итог

Версия помечена v1.5 - это чисто внутренний фикс диагностики (не
пользовательская фича), но по факту первый настоящий "баг в моём же коде
этой ветки сессий" - раньше все находки были про сам движок, эта - про
качество ИНСТРУМЕНТА ДИАГНОСТИКИ, которым я же и пользуюсь для будущих
расследований. Стоит взять за привычку: temporary debug-хуки, добавляемые
для расследования, ВСЕГДА проверять полным traceback (`except Exception`
+ `traceback.print_exc()`), а не только `str(DecompileAbort)` - иначе
именно такие NameError/AttributeError в СОБСТВЕННЫХ временных правках
незаметно маскируются тем же защитным поясом, что защищает от чужих
ошибок в движке.
