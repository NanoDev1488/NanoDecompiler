## 1. Мини-язык для списка сайтов проверки легитимности/исходников

Сейчас `legitimacy_check.py` жёстко прошит на 4 источника (GitHub/
Modrinth/SpigotMC/RuSpigot) прямо в Python-коде - чтобы добавить пятый
сайт, нужно лезть в код и пересобирать движок. План - вынести список
сайтов в отдельный конфиг-файл (свой формат, не просто голый JSON - у
пользователя есть конкретные требования к нормализации данных, которые
JSON сам по себе не выражает), хранящийся на GitHub (в репозитории
проекта, НЕ в релизах - подтягивается движком по URL на raw.githubusercontent.com
или аналогично), с локальным кэшем на диск на случай отсутствия сети.

### Формат (черновик от пользователя, причёсан)

Одна запись списка - один сайт:

```
{
  "site": "site.com/",
  "query": "?search={plugin_name}",
  "release_query": "/releases",
  "size_units": "bytes"
}
```

Поля:
- `site` - базовый URL источника.
- `query` - шаблон поискового запроса. `{plugin_name}` - ПОДСТАВЛЯЕТСЯ
  движком, не сайтом - см. правила нормализации ниже.
- `release_query` - шаблон для поиска СРЕДИ РЕЛИЗОВ конкретно (не общий
  поиск) - должен возвращать: имя, версию, хэш, размер файла.
- `size_units` (или аналог) - в чём сайт отдаёт размер (byte/KB/MB) -
  движок сам конвертирует для показа пользователю (МБ/КБ по величине,
  не сырые байты).
- Формат ДОЛЖЕН быть расширяемым - у записи может со временем
  понадобиться ещё поле (например заголовки авторизации, rate-limit,
  формат ответа) - схема не должна быть "закрытой".

### Нормализация `{plugin_name}` (правила от пользователя, дословно
### перенесены)

Перед подстановкой в `query`/`release_query`:
1. Убрать версию из имени - если имя заканчивается на что-то похожее на
   версию (число, `v`+число, смешанные цифробуквенные версии типа
   `2_1_90`, `-1.2.3` и т.п.) - отрезать этот хвост.
2. Если получившееся имя (БЕЗ учёта `.jar` и версии) короче 2 символов -
   на этом сайте вообще не искать (слишком общий запрос, бессмысленно/
   шумно).

### Сверка хэша - формат сообщения (от пользователя, причёсан)

Если хэш локального плагина НЕ совпадает с одним или несколькими
источниками, но совпадает с другими - сообщение должно явно разделять,
где совпало, а где нет, а не просто "не совпадает":

```
Хэш плагина не соответствует хэшу с сайтов: GitHub, SpigotMC.
Совпадает с: Modrinth.
```

(Не просто общий "подозрительно" - конкретно КАКИЕ источники согласны, а
какие нет - это разная степень доверия: если совпадает хотя бы с ОДНИМ
официальным источником, это уже не то же самое, что не совпадает вообще
ни с одним.)

### Где хранить и как читать

- Файл живёт в репозитории проекта на GitHub (НЕ в Releases - это
  ресурс/конфиг, не установочный артефакт) - например
  `resources/check-sites.json` (или `.ndcheck`, если делать реально свой
  формат/расширение - решить при реализации).
- Движок при каждой проверке легитимности тянет АКТУАЛЬНУЮ версию файла
  по прямому URL (raw.githubusercontent.com или аналог).
- **Обязательный локальный кэш** - последняя успешно скачанная версия
  сохраняется на диск (рядом с настройками, `get_app_data_dir()` уже
  есть в `gui_common.py`) - если сети нет, используется кэш, если кэша
  тоже нет - используется fallback ЖЁСТКО ВШИТЫЙ список (те же 4
  источника, что сейчас) - легитимность-проверка не должна ломаться
  полностью просто потому что нет сети/GitHub недоступен.
