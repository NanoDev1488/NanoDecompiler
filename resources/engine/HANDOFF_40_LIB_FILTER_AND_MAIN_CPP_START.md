## ЧТО СДЕЛАНО

Реализован и **протестирован на реальных jar** пункт "ПЕРВОЕ, что нужно
сделать правильно" из HANDOFF_39 (main.py, п.3 плана) - фильтрация
библиотечных классов ДО декомпиляции:

1. `pom_builder.hpp/.cpp`: `known_libs()` и `detect_lib()` вынесены из
   анонимного namespace в публичный API `nd::` (были приватными для самого
   файла - HANDOFF_39 просил их переиспользовать, но они были недоступны
   снаружи). `detect_lib()` теперь возвращает `std::optional<LibCoords>`
   (структура group/artifact/comment) вместо `std::optional<std::tuple<...>>`
   - один call-site в `build_pom()` обновлён под новую сигнатуру.
2. **Новый модуль** `include/lib_filter.hpp` + `src/lib_filter.cpp` - 1:1
   порт `_known_library_coords`/`_relocated_library_prefixes`/
   `_signature_relocated_prefixes` из `main.py` (строки ~461-529
   оригинала). Три публичные функции:
   - `relocated_library_prefixes(pom_xml_text)` - парсит `<relocations>`
     через уже существующий `parse_shade_relocations`.
   - `signature_relocated_prefixes(all_names)` - sqlite-jdbc native-путь
     сигнатура (единственная в оригинале на сегодня).
   - `known_library_coords(internal, extra_prefixes)` - главная функция,
     которую main.cpp будет дёргать на каждый класс перед декомпиляцией.
3. **НАЙДЕН И ИСПРАВЛЕН реальный баг данных**: в таблице `known_libs()` в
   pom_builder.cpp **отсутствовала `org.h2`** (база H2), хотя HANDOFF_39
   прямо называет её среди библиотек, которые Salaires-3_4_1.jar бандлит
   и которые НЕ должны декомпилироваться (тот самый файл, где искали
   var10-баг - `ToCharFunction.class` - это H2-класс!). Без этой записи
   фильтр пропускал 1049 h2-классов насквозь. Добавлено:
   `{"org.h2", "com.h2database", "h2", ...}`. Координаты (`com.h2database:h2`)
   - стандартные maven-координаты H2 (не сверялись с сетью - в песочнице нет
   интернета - НО это официальные и стабильные координаты проекта, высокая
   уверенность).

не дублирую здесь ради краткости (если нужно - просто перезапустить
`test_lib_filter` на архивах, ничего не меняется между запусками).

**ВАЖНО - вероятно, есть ЕЩЁ пропущенные библиотеки в таблице** - я не
сверял КАЖДЫЙ jar на предмет "остались ли там классы с явно
опубликованными, не-обфусцированными пакетными именами похожими на
известную библиотеку, которой нет в таблице" - только глазами пробежался
по выводу (не нашёл больше явных кандидатов кроме h2, но таблица могла
пропускать и другие; `betterstructures.jar` например тащит `javassist` +
`kotlin-stdlib` - оба УЖЕ есть в таблице, ОК). Стоит перепроверить это
эвристикой на "не-обфусцированное имя пакета, который сам не является
кодом плагина" при написании остальной части main.cpp (Renamer уже умеет
детектить `looks_obfuscated` - разница между "не обфусцировано, но и не
плагин" вручную не ловится нигде, кроме этой таблицы).
