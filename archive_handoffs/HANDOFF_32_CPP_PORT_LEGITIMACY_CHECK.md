## Новое: json_value.hpp/cpp (не Python-модуль - общая инфраструктура)

Python-оригинал использует stdlib `json.loads`. Написан компактный
рекурсивный JSON-парсер (объекты/массивы/строки/числа/bool/null,
стандартные `\uXXXX`-escape'ы с кодированием в UTF-8, упрощённо - без
полной обработки суррогатных пар вне BMP, что для полей вроде названий
репозиториев/проектов из ответов GitHub/Modrinth/Spiget более чем
достаточно). Порядок ключей объекта сохраняется (`vector<pair<...>>`, а
не map - как порядок вставки в Python dict).

### Найденные и исправленные баги ПОРТА (не в оригинале) - все из-за
### неверного обращения с C++ raw string literals `R"(...)"`

Первая версия файла не компилировалась/компилировалась с неверным
содержимым regex-паттернов из-за двух разных ошибок при ручном наборе:
1. Внутри `R"(...)"` НЕ нужно экранировать кавычки (`\"` - это ДВА
   символа, обратный слэш и кавычка, а не один символ кавычки) - по
   ошибке несколько паттернов были набраны с `\"`/`\\s` вместо `"`/`\s`,
   что меняло семантику regex.
2. Паттерн разбора ссылок RuSpigot содержит `([^"]+)"` - то есть
   ПОДСТРОКУ `)"`, которая для стандартного разделителя `R"( ... )"`
   означает ПРЕЖДЕВРЕМЕННОЕ окончание raw-строки (компилятор видит
   `)"` внутри самого паттерна и считает его концом литерала). Исправлено
   переходом на кастомный разделитель `R"RE( ... )RE"` для этого
   конкретного паттерна.
Оба класса ошибок пойманы на этапе компиляции (первая - ошибками/неверным
поведением при regex-тестах, вторая - прямой ошибкой компиляции) и
устранены до какой-либо сдачи модуля - в собранном/сверенном коде их уже
нет, но стоит держать в уме для всех будущих модулей с regex-паттернами,
содержащими literal `"` внутри себя (HTML/XML-парсинг паттерны - кандидаты
на этот же класс ошибки).

### Регрессия (только офлайн-часть - см. оговорку выше)

- `fields_from_plugin_yml`: 3 синтетических `plugin.yml` (простой
  `website`/`author`, список `authors: [...]` в разных кавычках, файл без
  контактной информации) - **полное совпадение** с оригиналом.
- `ruspigot_parse_result_links` (regex): синтетический HTML с 4 ссылками
  (2 должны матчиться по классу, 2 - нет/не тот класс) - **полное
  совпадение** порядка и содержимого найденных пар (href, title) с
  оригинальным `_RUSPIGOT_RESULT_RE.findall`.
- `json_parse`: сверено на реалистичном JSON-примере (вложенные
  объекты/массивы, юникод-escape `\u0041\u00e9\u4e2d` -> "Aé中",
  экранированные кавычки внутри строк) - **точное совпадение** с
  `json.loads` на уровне извлекаемых значений.
