# HANDOFF_22: v1.6 - большой GUI+перф раунд

Движок не менялся в этом раунде (регрессия на всех 12 jar подтверждена
идентичной v1.5 - 308/315 EryBuyer и т.д.). Всё ниже - клиент
(`electron/`, `src/`) + одна централизация версии в `main.py`.

## 1. Версия в CLI годами показывала "v1.2"

Пользователь прямо указал: "в CLI всё ещё пишет версия 1.2". Проверка
показала - я в HANDOFF_16 централизовал версию для CI/package.json, но
**НЕ проверил сам `main.py`** - там было ТРИ независимых хардкода
`"NanoDecompiler v1.2"` (докстринг модуля, константа
`NANO_DECOMPILER_VERSION`, литерал внутри `print_banner()`). Свёл в одно
место - `NANO_DECOMPILER_VERSION` теперь единственный источник,
докстринг оставлен текстом (Python не даёт интерполировать в docstring)
с явным комментарием-напоминанием сверху файла.

## 2. Плашка результата - была маленькая, теперь крупная и с процентом

Раньше "готово" - это была мелкая пилюля (`.status-row`, 12px шрифт),
легко пропустить. Добавили парсинг строки `Методов декомпилировано:
X/Y (Z%)` из живого лога движка (`App.tsx::onLog`) - при завершении
показывается крупная цветная карточка (`.result-card`) с процентом и
кнопками "Открыть папку"/"Открыть в VS Code" внутри неё же.

## 3. Иконка настроек рисовалась квадратом

Юникод-символ ⚙ (U+2699 GEAR) не входит в базовые шрифтовые блоки,
которые гарантированно есть на любой системе - на части систем
рендерился как placeholder-квадрат ("неизвестный символ"). Заменили на
inline SVG (свой path, не зависит от шрифта). Заодно добавили небольшой
набор Material Symbols (Google, Apache License 2.0) как переиспользуемый
компонент `Icon` - `folder_open`/`code`/`check_circle`/`error`/
`refresh`/`cloud_download` - paths вшиты прямо в код (в песочнице нет
сети на npm-реестр, реальный пакет `material-icons` подключить не
вышло - см. ограничение ниже).

## 4. "Лагает всё" - главная причина: батчинг лога

Каждая строка лога движка слалась ОТДЕЛЬНЫМ IPC-сообщением
(`electron/main.ts`) и вызывала ОТДЕЛЬНЫЙ React-рендер
(`setLines((prev) => [...prev, line])` в `App.tsx`) - на jar с тысячами
методов это могло означать сотни рендеров за секунды, конкурирующих с
компоузером браузера за кадры (отсюда и ощущение "лагает всё", включая
несвязанные анимации вроде toast-плашки). Исправлено:
- `main.ts` теперь копит строки и шлёт их ПАЧКАМИ (троттлинг ~40мс).
- `App.tsx` добавляет весь батч ОДНИМ `setLines`, а не по одной строке.
- Лог ограничен `MAX_LOG_LINES = 4000` - старые строки обрезаются, чтобы
  DOM не рос бесконечно на очень крупных jar.

## 5. Определение размера/пакетов jar - было медленным

Реальная причина: КАЖДЫЙ выбор jar в интерфейсе спавнил ОТДЕЛЬНЫЙ
Python-процесс (`python3 main.py --jar-summary ...`, или собранный
`.exe`) - для PyInstaller onefile-сборки это ЕЩЁ И самораспаковка exe во
временную папку НА КАЖДЫЙ вызов (известная особенность `--onefile`) -
десятки-сотни миллисекунд лишних на каждый выбор файла.

Написал `electron/jarSummary.ts` - читает central directory ZIP-формата
напрямую в Node (без внешних зависимостей, только `fs`/`zlib` из
stdlib) - размер/список классов/пакетов без запуска движка вообще.
Версия Java и имя плагина требуют распаковки двух маленьких файлов
(первый `.class` - 8 байт заголовка; `plugin.yml` целиком) - через
`zlib.inflateRawSync`, тоже без внешних зависимостей. ZIP64 (jar'ы за
4ГБ/65535+ записей - на практике не встречается у Bukkit-плагинов)
сознательно не поддержан - при малейшем подозрении на месте бросается
исключение, и `jar:summary`-хендлер откатывается на старый путь через
Python-подпроцесс (корректность важнее скорости на редком edge-case).

## 6. Обновления: прогресс скачивания, пауза автопроверки, релиз/бета

- `httpsDownloadFile` (`electron/updater.ts`) теперь репортит прогресс
  (скачано/всего) через throttled callback (не чаще раза в ~120мс - та
  же логика троттлинга, что и у батчинга лога).
- `App.tsx` считает скорость (по дельте между семплами) и ETA сам,
  показывает прямо в шапке (скачано/всего · скорость · осталось), по
  клику на плашку открывается подробная карточка (прогресс-бар + сетка
  метрик) - это и есть "мини-GUI по клику", который просил пользователь.
- Автопроверка обновлений теперь СТАВИТСЯ НА ПАУЗУ, пока идёт активное
  скачивание/установка (`updateState === "applying" || installingClient`)
  - раньше продолжала дёргать сеть прямо во время скачивания, без
    всякого смысла.
- Версии теперь классифицируются: РОВНО два числа через точку (1.4, 1.5,
  1.6) - релиз; три и больше (1.4.1, 1.4.2) - пререлиз/бета. Показывается
  бейджем рядом с номером версии при найденном обновлении.

  показывает, что построчная проверка руками ловит не всё; собрать и
  открыть вживую перед раздачей всё ещё нужно.
