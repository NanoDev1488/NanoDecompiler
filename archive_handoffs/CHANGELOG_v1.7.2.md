# v1.7.2

## Починили

- Подсветка `.properties`-файлов не работала вообще — файлы этого типа
  ошибочно роутились на YAML-токенизатор, который понимает только `:`
  как разделитель ключ/значение, а не `=`. Ключи никогда не подсвечивались.
  Добавлен отдельный токенизатор, который понимает оба разделителя.
- `.json`-файлы в просмотрщике показывались одной нечитаемой строкой —
  движок пишет компактный JSON без переносов. Теперь во вьюере (только
  для отображения, сам файл на диске не трогаем) JSON красиво
  форматируется; если он вдруг невалиден, тихо показываем как есть.
- `META-INF/LICENSE*` и `META-INF/NOTICE*` (лицензии библиотек,
  забандленных maven-shade-plugin) всё ещё протекали в
  `src/main/resources` наравне с MANIFEST.MF/подписями — не относятся
  к коду плагина, теперь отфильтрованы.
- В каждый декомпилированный `.java`-файл теперь добавляется футер
  "Декомпилировано NanoDecompiler — t.me/NanoDev_mc" (требование EULA).
- Параметры канонического конструктора `record`-класса теперь всегда
  совпадают с именами компонентов записи, как того требует JLS — раньше
  при отсутствии debug-информации в `.class` они могли остаться как
  `arg0`/`arg1`. Переименование синхронизировано между сигнатурой и телом.
- `pom.xml`, генерируемый для Velocity/BungeeCord-плагинов без
  Bukkit-style `plugin.yml`, брал `artifactId` из имени файла jar —
  теперь использует уже распознанное имя плагина из
  `velocity-plugin.json`/`bungee.yml`, если оно есть.
- Отчёт эвристического антивирус-сканера указывал только "найдено
  где-то в jar" — теперь для найденных паттернов перечисляются конкретные
  классы, где они сработали.
- Плашки "N классов" в сайдбаре и статус-баре путали с числом из
  терминала ("X из Y методов декомпилировано") — это два принципиально
  разных подсчёта (весь архив, включая забандленные библиотеки, против
  кода именно плагина). Явно подписали как "N классов **в архиве**".
- Автопрокрутка терминала была резким скачком на каждую пачку логов —
  теперь плавная анимация (кроме случая очень большого отставания —
  там по-прежнему мгновенный прыжок, чтобы не отставать от лога).

## Добавили

- Кнопка "свернуть/развернуть всё" в дереве файлов — на jar с
  большим количеством пакетов сворачивать их по одному было неудобно.
- Группировка "(корень)" в дереве файлов разделена по расширению —
  default-package `.java`-классы больше не мешаются в одной куче с
  `pom.xml`/`config.yml` и прочими корневыми ресурсами.
- Проверка на пустые сгенерированные классы: если у класса реально были
  поля/методы в байткоде, но все распознаны как служебные (accessor/
  synthetic-bridge/тривиальный конструктор) и не напечатаны — теперь это
  явно поясняется комментарием вместо молчаливой пустоты. Подтверждено
  на реальном `NoLoanPermittedException` из EssentialsX.
- **Полноценно реализована реконструкция аргументов конструктора enum**
  (была системная проблема — встречалась в 32 из 32 тестовых jar с
  enum'ами): раньше `<clinit>` enum'а всегда обходился стороной, константы
  печатались голыми именами без аргументов конструктора — не
  компилировалось без ручной правки. Теперь `<clinit>` декомпилируется
  ТЕМ ЖЕ путём, что и обычный `static{}`, и для каждой константы вида
  `EnumType.CONST = new EnumType(имя, ordinal, арг1, арг2, ...);` (ровно
  так их компилирует javac) реальные аргументы (после отбрасывания двух
  синтетических — имени и ordinal) подставляются прямо в объявление
  константы: `CONST(арг1, арг2)`. Заодно восстанавливается ЛЮБАЯ
  дополнительная static-инициализация в `<clinit>` enum'а сверх
  конструирования констант (например заполнение lookup-таблицы
  `Map<String, EnumType>` по значениям — раньше терялось молча,
  подтверждено на реальном классе `CasinoType` из тестового корпуса —
  метод `getType(String)` теперь реально работает в декомпилированном
  виде, а не просто существует с пустой картой).
  Если форма `<clinit>` не укладывается в ожидаемый паттерн (например
  анонимное тело константы `RED { ... }` — компилируется в отдельный
  синтетический подкласс) — безопасный откат на честное предупреждение
  для ВСЕГО enum'а целиком (частичная/угадываемая реконструкция
  сознательно не делается, во избежание тихо-неверного результата).
  Проверено на 32 реальных jar — 0 регрессий, 0 несбалансированных
  скобок, несколько успешных откатов на реальных jar (constants с
  анонимными телами) подтверждают, что защитная проверка срабатывает
  корректно, а не даёт ложноположительный "успех".
- Честное предупреждение про ограничение enum-конструкторов добавлено
  в секцию "ЧЕСТНО О ГРАНИЦАХ" файла README_RU.txt — актуально для
  оставшихся случаев отката (анонимные тела констант).

## Не доделали (на будущее)

- Мини-инфо панель (`jar_summary.hpp`/`jarSummary.ts`) по-прежнему
  считает ВСЕ классы в архиве, включая библиотеки — полноценный учёт
  фильтра библиотек (`known_libs()`) в панели "до декомпиляции" не
  сделан: пришлось бы дублировать таблицу известных библиотек в
  TypeScript, что создаёт риск расхождения между C++ и Node путями
  (см. предупреждение про единый источник версии в HANDOFF_16 — тот же
  принцип применим и здесь). Сделали честную подпись вместо дублирования
  логики — см. "Починили" выше.
- Platform display (`kind_label()`) — проверено, уже используется
  правильно везде (и в предупреждении про моды, и в stats_json), пункт
  из предыдущего хэндофа оказался неактуален/уже исправлен раньше.
- Enum-константы с анонимным телом (`RED { public String toString(){...} }`)
  по-прежнему не реконструируются (безопасный откат на честное
  предупреждение) — компилируются в отдельный синтетический подкласс,
  для полноценной поддержки нужна отдельная сессия.
- `<clinit>` для enum'а НЕ считается в статистике "X из Y методов" ни
  в одном из путей (ни при успешной реконструкции, ни при откате) —
  сохранено намеренно, чтобы не менять знаменатели процентов у всего
  тестового корпуса при этом фиксе (см. обсуждение в HANDOFF).
