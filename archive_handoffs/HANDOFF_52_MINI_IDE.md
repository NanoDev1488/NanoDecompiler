# HANDOFF_52: мини-IDE в GUI (HANDOFF_39 п.2, порядок 2->1->3)

Продолжение HANDOFF_51. Пользователь попросил взяться за GUI-бэклог из
старого мастер-хэндофа (HANDOFF_39) в порядке: мини-IDE -> мини-язык
легитимности -> редизайн -> остальное. Также уточнил: 66 плагинов из
`plugins-for-test.zip` НЕ были загружены случайно (вопреки моему
предположению в более ранней сессии) - учитывать это при дальнейшей
работе с тестовым корпусом.

## ЧТО СДЕЛАНО

Файловый проводник + просмотр/редактирование декомпилированных файлов
прямо в GUI, без необходимости открывать внешний редактор.

1. **`electron/main.ts`** - два новых IPC-хендлера:
   - `fs:listDir(root, relDir)` - список ОДНОГО уровня директории (ленивая
     подгрузка при раскрытии узла дерева - у крупных проектов вроде
     BukkitOfUtils, 618+ файлов, строить весь рекурсивный список сразу
     дорого и не нужно).
   - `fs:readTextFile(root, relPath)` - чтение файла с лимитом 4 МБ и
     эвристикой "это бинарник" (нулевой байт в первых 8000 байтах - тот
     же трюк, что использует `git` для binary-detection).
   - **Безопасность**: оба хендлера проверяют, что итоговый путь ДЕЙСТВИТЕЛЬНО
     лежит внутри переданного `root` (через `path.resolve` + `startsWith`
     с проверкой границы разделителя) - `renderer` не может прочитать
     произвольный файл системы через эти функции.
2. **`electron/preload.ts` + `src/global.d.ts`** - типизированный доступ
   (`window.nano.listDir`/`readTextFile`), синхронизировано в обоих местах
   (как и раньше - см. HANDOFF_51 про этот же паттерн).
3. **`src/MiniIde.tsx`** (новый файл) - сам компонент: дерево файлов слева
   (ленивая подгрузка, иконки по типу файла) + редактор справа
   (CodeMirror 6). Подсветка синтаксиса для `.java`/`.xml`/`.yml` (то, что
   реально встречается в выводе движка) - остальное как обычный текст.
   Тема редактора - самодельная, на тех же CSS-переменных, что и весь
   остальной интерфейс (не готовая npm-тема - чтобы не выглядело
   вставленным чужеродным куском).
4. **`src/App.tsx`** - кнопка "Открыть мини-IDE"/"Показать лог" в
   result-card (переключает `.terminal` на `<MiniIde>` и обратно, доступна
   только когда есть `outDir`); сброс `showIde` при старте нового прогона
   декомпиляции (иначе IDE показывала бы файлы ПРЕДЫДУЩЕГО проекта, пока
   идёт декомпиляция нового).
5. **`src/styles.css`** - стили панели (`.ide-*`) + новый `.btn-text`
   (мелкая текстовая кнопка, которой раньше не было).
6. **`package.json`** - добавлены зависимости `@uiw/react-codemirror` +
   `@codemirror/lang-{java,xml,yaml}`. CodeMirror 6 выбран вместо Monaco
   Editor - Monaco требует отдельной настройки web worker'ов под Vite,
   это реальный риск сломать сборку без возможности проверить живьём.

## ПОЧЕМУ CodeMirror, А НЕ Monaco

Monaco Editor (то, на чём основан VS Code) даёт более "настоящее" IDE-
ощущение, но требует явной настройки бандлинга web worker'ов (через
`vite-plugin-monaco-editor` или ручной конфиг) - в этой сессии нет
возможности живьём собрать и проверить (`npm install`/`vite build` ни
разу не запускались за всю историю проекта в песочнице, см. HANDOFF_45).
CodeMirror 6 не требует специальной настройки под Vite вообще - ниже
риск сломать сборку вслепую. Если в будущем понадобится "более настоящий"
редактор - Monaco можно добавить отдельной сессией с реальной проверкой
сборки.

## ЧЕСТНО ПРО ГРАНИЦЫ

- **НЕ ПРОВЕРЕНО ЖИВОЙ СБОРКОЙ** - нет сети на npm-реестр в песочнице
  сессии (те же ограничения, что в HANDOFF_45/51). Код проверен глазами +
  структурной сверкой (баланс скобок, соответствие типов между
  `preload.ts`/`global.d.ts`), но `npm install` реальных пакетов ни разу
  не выполнялся.
- Редактор технически РЕДАКТИРУЕМЫЙ (`editable={true}`), но изменения
  НЕ сохраняются на диск - нет `fs:writeTextFile` хендлера (сознательно
  не делал - "мини-IDE" из спецификации HANDOFF_39 не уточняла, нужно ли
  сохранение, а молча позволять редактировать декомпилированный код без
  явного "Сохранить" было бы confusing UX - оставлено на будущее, если
  понадобится).
- Resizable-панелей нет - ширина дерева файлов фиксирована (260px) -
  можно добавить позже, не критично для первой версии.
