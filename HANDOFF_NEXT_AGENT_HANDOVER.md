## ТЕКУЩЕЕ состояние - незакоммиченная работа "1.9.6" (версия НЕ бампнута!)

`package.json`/`version.hpp` всё ещё говорят `1.9.5` - следующий агент
сам решает номер версии для этой пачки правок при выпуске. Полная
регрессия/пересборка НЕ проводилась для этого блока - только точечные
`tsc`-проверки (все чистые, см. ниже).

Файлы, изменённые в этом незавершённом блоке (все правки реальные, не
черновики - но НЕ собраны в архив и НЕ регрессированы всем корпусом):

1. **`src/state/engine.tsx` - `saveSettings()` - КРИТИЧНЫЙ БАГ-ФИКС,
   ГОТОВ.** Была жёстко прописана отправка ТОЛЬКО 3 старых полей
   (`legitimacyCheck`/`autoUpdateCheck`/`appIcon`) на диск через
   `window.nano.setSettings({...})` - `language` (с v1.7.6),
   `telemetryEnabled`/`telemetryUrl` (с v1.8.4) НИКОГДА не попадали в
   settings.json. В рендерере `setSettings(next)` обновлял ЛОКАЛЬНЫЙ
   стейт мгновенно - в UI выглядело, что сработало - но `main.ts`
   (`telemetry:sendReport`) на каждый вызов читает `loadSettings()`
   ЗАНОВО С ДИСКА - там `telemetryEnabled` так и оставался `false`. Это
   ТОЧНАЯ причина жалобы "багрепорт пишет выключено, хотя я включал".
   Теперь отправляется весь объект `next` целиком.

2. **`src/state/engine.tsx` - `collectSourceFiles()` - БАГ-ФИКС, ГОТОВ.**
   `pkg` хранился как путь с точками вместо слэшей (`.replace(/\//g,
   ".")`), а потом FileTree/CodeView СНОВА делили эту строку по точке -
   литеральная точка в имени папки (`"lang/v1.2"`) превращалась в лишний
   уровень вложенности (`v1` -> `2`). Убрал `.replace`, `pkg` теперь
   настоящий путь со слэшами. Визуально ничего не меняется - дерево и
   крошки и так рисуют `/` между сегментами.

3. **`src/components/FileTree.tsx` + `src/components/CodeView.tsx` -
   ГОТОВО.** Разбивка `f.pkg`/`file.pkg` изменена с `.split(".")` на
   `.split("/")` - следствие правки #2 выше, найдены ВСЕ места через
   `grep -rn "\.pkg\b"` по всему `src/`, ничего не пропущено.

4. **`src/components/PluginDetailsModal.tsx` - путь embedded-jar,
   БАГ-ФИКС #2, ГОТОВ (но НЕ проверен живьём пользователем ещё раз).**
   Пользователь снова пожаловался на неверный путь ПОСЛЕ фикса из v1.8.4
   (там был добавлен префикс `src/main/resources/`, но ручная логика
   `relPath.split("/").join(sep)` могла дать сбой, если zip-запись внутри
   jar использует ОБРАТНЫЕ слэши - `split("/")` их не находит вообще).
   Переписал на посегментную сборку через `joinOutDir()` (та же функция,
   что уже используют `addJarPaths` и остальной код) -
   `["src","main","resources", ...relPath.split(/[/\\]+/).filter(Boolean)]
   .reduce((acc, seg) => joinOutDir(acc, seg), job.outDir)`. Это
   МАТЕМАТИЧЕСКИ должно быть надёжнее старой версии, но раз пользователь
   уже дважды сообщал об этом баге - ОБЯЗАТЕЛЬНО попроси его
   переприслать jar с вложенным jar (например `NanoCore-bundle.jar`, он
   уже присылал раньше) и лично проверить, что кнопка реально работает,
   прежде чем закрывать этот пункт.

5. **`electron/main.ts` - `env:check` - ЧАСТИЧНО ГОТОВО.** Добавлено поле
   `inPath: boolean` в результат проверки java/maven - раньше приложение
   ЧЕСТНО запускало `mvn --version`/`java --version` по найденному
