# v1.7.3 «Ясность»

Первый релиз без суффикса BETA — кодовое имя вместо статуса. Секция
EULA "BETA STATUS" обобщена под "ACTIVE DEVELOPMENT" (юридическая суть
та же - ПО может содержать баги и меняться без предупреждения - просто
больше не привязана к конкретному слову в номере версии).

## Починили

- **Баннер в консоли был визуально сломан** на кириллице: ширина рамки
  считалась в БАЙТАХ (`std::string::size()`), а не в символах — каждый
  кириллический символ занимает 2 байта в UTF-8, поэтому рамка получалась
  непропорционально широкой, а отступы между строками "гуляли". Теперь
  считаем настоящую видимую ширину (кодовые точки UTF-8).
- **Прогресс-бар "замирал" на маленьком проценте на больших/сложных jar**
  (жалоба "2% за 16 секунд" на файлах вроде ViaVersion): индикатор двигался
  только по событиям вывода в консоль, а движок может подолгу молчать на
  тяжёлых классах (структуризация CFG) без единой строки лога. Теперь
  прогресс дополнительно ведётся по прошедшему времени (плавная асимптота),
  никогда не виснет надолго независимо от активности лога.
- `MAPPING_RU.txt` печатал сырые JVM-дескрипторы методов/полей
  (`(Ljava/lang/String;I)V`, `Lme/arcaniax/hdb/enums/CategoryEnum;`) —
  нечитаемо без знания формата байткода. Теперь конвертируются в обычные
  Java-сигнатуры (`(String, int): void`, `me.arcaniax.hdb.enums.CategoryEnum`).

## Добавили

- **Реальное вложенное дерево для ресурсных папок** (`lang/messages/admin/`
  и т.п.) — раньше каждая точная комбинация пути была одной плоской строкой
  без возможности свернуть родительскую папку целиком. Теперь настоящая
  рекурсивная раскрываемая структура с подсчётом файлов на каждом уровне.
  Ограничено ТОЛЬКО ресурсными файлами — Java-пакеты показываются как
  раньше, одной строкой на полный путь (на это никто не жаловался, трогать
  без запроса — лишний риск). "Свернуть/развернуть всё" работает на всех
  уровнях вложенности. Логика проверена скриншотами через Playwright на
  автономном HTML-мокапе (само GUI пересобрать в песочнице нельзя —
  npm-реестр недоступен) — 3-уровневая вложенность, точечное сворачивание
  одной папки, массовое сворачивание всего дерева — всё работает корректно.
  Настоящий Electron-сборку всё равно стоит проверить глазами.

## Продолжение (второй заход v1.7.3 - реальные баги + новые фичи)

### Починили (критичные, найдены сторонним ревью + подтверждены самостоятельно)

- **Реконструкция enum-констант не работала на обфусцированных enum'ах** —
  сравнивалось сырое имя поля с уже переименованным (`fa->name` из AST -
  дружелюбное, `f->name` из `enum_const_fields` - сырое). На неофбусцированных
  enum'ах (raw==friendly случайно совпадают) баг маскировался - именно
  поэтому не поймал его при тестировании в первый раз. На обфусцированных
  (то есть в большинстве реальных целей этого инструмента) реконструкция
  тихо ВСЕГДА откатывалась на голые имена. Независимо тем же способом
  нашёл и починил друг пользователя — двойное подтверждение, что баг
  настоящий.
- **curl на Windows** — `2>/dev/null` и одинарные кавычки не работают в
  cmd.exe (не bash). Экранирование и редирект теперь platform-specific.
- **Установщик Java/Maven** мешал stdout+stderr в один буфер (ломало
  JSON.parse на валидных строках) и терял последнюю строку без `\n`.
- **Плавный скролл терминала навсегда убивал автопрокрутку** (регрессия
  из предыдущего раунда v1.7.3) — промежуточные scroll-события во время
  smooth-анимации сбрасывали "прилипание" к низу. Починено флагом
  "это мы сами скроллим", плавность сохранена.
- **Обновление .exe на Windows** — отсутствие `res.resume()` на редиректах
  HTTPS-запросов вешало сокеты; `renameSync` падал поверх файла,
  заблокированного антивирусом/открытым хендлом.
- **`window.nano.checkEnv()` был не объявлен в `global.d.ts`** — реально
  существовал в `preload.ts`, но TypeScript не знал о нём (рассинхронизация
  типов, поймано при финальной проверке `tsc`).
- **Линковка Windows-сборки** (`CMakeLists.txt`) — подозрительная
  `-Wl,-Bstatic -lwinpthread -Wl,-Bdynamic` могла расщеплять рантайм на
  статическую и динамическую часть, что похоже на причину нового
  CI-краша `STATUS_STACK_BUFFER_OVERRUN`. Исправлено, но **не подтверждено
  на реальной Windows** — добавлен диагностический шаг с gdb-бэктрейсом
  в CI на случай повтора.
- `vite.config.ts` → `vite.config.mts` (ESM-совместимость, подтверждено
  реальной сборкой у стороннего разработчика с рабочим `package-lock.json`
  — сам собрать `npm install` в песочнице не могу).

### Добавили

- **Настраиваемая сортировка списка файлов** — кнопка-циклер (имя → размер
  по LOC → сначала файлы с предупреждениями движка) в шапке дерева файлов.
  Сортирует файлы внутри пакетов/папок; сама структура дерева остаётся
  алфавитной (предсказуемая навигация).
- **Установка Java/Maven прямо из настроек** — backend (`tools:install`/
  `tools:progress`) уже существовал с более ранней сессии, не хватало
  кнопки в GUI. Кнопка "Установить" + живой прогресс (текст + процент)
  в строках Java/Maven настроек, блокировка второй установки поверх первой.
- Малварь-предупреждения и другие "ВНИМАНИЕ:"-строки (несовпадение хэша
  jar, проблемы баланса скобок при верификации) теперь классифицируются
  правильно в терминале GUI (были "info", терялись в потоке лога).
- Более точная реконструкция прогресс-бара по времени (плавнее растёт в
  первые секунды, стартует не с пугающих "2%", а с 5%).
- `META-INF/proguard/*` (правила библиотек) больше не протекают в вывод.
- Подсветка JSON во вьюере (раньше только pretty-print без цвета).

### Не подтверждено / требует реального теста

- Гипотеза про причину `STATUS_STACK_BUFFER_OVERRUN` в Windows CI — лучшая
  версия по итогам статического анализа линковки, не проверена вживую.
- Прогресс-бар "2%" — пользователь тестировал v1.7.2 (без time-based
  экстраполяции и без реального прогресс-бара от движка вообще, это всё
  добавлено только в v1.7.3) - вероятно уже решено, но не подтверждено на
  актуальной сборке.
